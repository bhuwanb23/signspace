# P0.6 — Repo hygiene, baseline commit, and branch policy

**Phase:** P0 · **Est:** 30 min · **Depends on:** nothing · **Workstream:** W5
**Gate fed:** G0

## Why this exists
This repo is the project's memory. On Day 9 at 2 a.m. the difference between shipping and not is whether the state of the build is legible.

## Do this
1. Confirm `.gitignore` covers Unity `Library/`, `Temp/`, `Build/`, `Logs/`, keystores except debug.
2. Create `phases/` structure (this folder tree) and commit it.
3. Adopt the branch policy: `main` always buildable, one branch per phase named `pN-slug`.
4. Add the two helper scripts to the workflow: `scripts/status.py` and `scripts/count.py`.
5. Make the baseline commit with a message naming the phase state.

## Done when
- [ ] `git log` shows a baseline commit
- [ ] `main` builds (or is honestly empty at this point)
- [ ] Branch policy written down

## Artefacts produced
- Baseline commit
- `docs/05-build/DEFINITION-OF-DONE.md` branch rules

## Traps
- Committing `Library/` — it is gigabytes and will destroy clone time
- Working directly on `main` from Day 3 onward
