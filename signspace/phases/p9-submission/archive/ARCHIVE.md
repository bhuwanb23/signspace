# P9.8 — Archive

**Phase:** P9 · **Task:** P9.8 · **Gate:** G9 · **Written:** 17 Nov 2026

> The submitted build is `v1.0-competition`. This directory holds the record of what was submitted,
> so that on 11 Dec (winners announced) or on any future day, the exact state of the entry can be
> reconstructed without guessing.

---

## What goes here

| File | What it is | Source |
|---|---|---|
| `BUILD.md` | the frozen build record: version, SHA-256, commit hash, build command, device requirements | generated by `SIGNSPACE/P9.1 Freeze the build` |
| `submitted.md` | the freeze record, the Devpost submission ID, the confirmation email, the invite URL | filled in on P9.6 |
| `shot-list.csv` | the 14 shots, their timecodes, and which were captured | `phases/p9-submission/shot-list.csv` |
| `edit-notes.md` | the edit decisions: what was cut, what was kept, why | P9.4 |
| `channel-state.png` | screenshot of the `Competition` channel with the uploaded build | P9.2 |
| `count-output.txt` | the output of `scripts/count.py` at submission time | P9.5 |
| `video-master/` | the video master file (out of git — too large) | P9.4 |

## The freeze record

See `phases/p9-submission/submitted.md`.

## The tag

```bash
git tag v1.0-competition
git push origin v1.0-competition
```

The tag points at the commit that produced the submitted APK. After this, `main` is frozen:
no commits, no edits, no "one small fix".

## The rule

**Nothing changes after the entry period ends.** The competition states: *"Judging is based on the
state of the Entry at the submission deadline."* A build that is wrong at submission is wrong
forever. A fix applied after submission is a disqualification.
