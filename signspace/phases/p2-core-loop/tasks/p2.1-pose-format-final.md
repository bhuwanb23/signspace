### What actually changed, and the two findings

**The format was already v1 and had three copies of its own rules** — `make_pose.py`,
`make_probe_poses.py` and `validate_poses.py` each carried a private `validate()`, and the probe copy was
weaker than the shipped one. The rules now live in `pose_schema.py`; the other three call it. The
device loader (`HandPose.cs`) stays an independent implementation **on purpose** — one shared
implementation would mean a bug that agrees with itself.

**Finding 1 — the validator had an ordering bug, found by the self-test on its first run.** `validate()`
checked the version-2 required fields before migrating a version-1 file, so it would have rejected every
legacy file for missing the very fields migration exists to supply. No shipped file exercises that path;
a hand-run test would never have found it.

**Finding 2 — POSE-FORMAT §4 claimed "no normalisation of the user is needed at all", which is true of
the *data* and not of the *format*.** The six shipped poses declare `signer: synthetic-neutral-v1`,
whose neutral is identity by construction, so live local rotations can be compared directly. A pose
captured from a real signer would be in that person's neutral frame and would **require** a per-user
neutral capture (`rel = inverse(q_neutral_user) * q_live`). That is now written as a contract that
branches on `signer` (§4.1), and `NeutralCapture` is a **P2.2** deliverable rather than something to be
invented mid-implementation.

### Why the rename was worth 4 hours of churn

`jointNames → joints`, `q → rot`, `neutralCaptured → captured`. P2.1 is the last moment this is cheap:
every downstream system reads this file. `rot` names the axis order that `q` hid, and `signer` is the
field that makes a relative rotation re-capturable at all. Schema 1 stays **readable** through two
agreeing migration paths (on disk via `--migrate`, in memory via `HandPose.MinReadableVersion`), which is
the migration path the task's trap asks for — proven on a real v1 file, not just described.

Both traps answered:
- *Absolute world rotations* → `rot` is neutral-relative by definition, and `signer` names the neutral.
- *No migration path* → two independent paths, both tested; unknown versions still refused loudly.
