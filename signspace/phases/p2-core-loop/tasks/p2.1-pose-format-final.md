# P2.1 — Finalise the pose format and the capture-neutral contract

**Phase:** P2 · **Est:** 1.5 h · **Depends on:** P1.4 · **Workstream:** W2
**Gate fed:** G2

## Why this exists
Every downstream system — matching, capture, the shelf, near-miss — reads this one file format. Getting it wrong on Day 3 means rewriting on Day 8, when there is no room.

## Do this
1. Freeze the schema: `version`, `id`, `handedness`, `signer`, `captured`, `vantage`, `joints[]` (26 names), `rot[]` as XYZW quaternions **relative to that signer's neutral capture**, `confidence` metadata.
2. Define the neutral capture procedure precisely: relaxed open hand, palm down, held 2 s, averaged over 60 frames.
3. Add a schema validator script (`scripts/validate_poses.py`) that fails loudly on joint-count or normalisation errors.
4. Generate three sample poses and check them in as fixtures.
5. Write `docs/02-tech/POSE-FORMAT.md` in full, including the left-hand mirroring rule.

## Done when
- [ ] Schema frozen and documented
- [ ] Validator script runs and catches a deliberately broken file
- [ ] Three fixture poses committed

## Artefacts produced
- `docs/02-tech/POSE-FORMAT.md` (complete)
- `scripts/validate_poses.py`
- `unity/Assets/StreamingAssets/Signs/*.json` fixtures

## Traps
- Storing absolute world rotations — user hand size then changes the shape
- Forgetting `version` and having no migration path on Day 9
