# P2.3 — Three bands, no failure state

**Phase:** P2 · **Est:** 1 h · **Depends on:** P2.2 · **Workstream:** W2
**Gate fed:** G2

## Why this exists
The product never tells a learner they are wrong in the abstract — it tells them how far they are and in which direction. That behaviour is a hard design commitment (ADR-003), and it lives in this threshold set.

## Do this
1. Define three bands over `D`: **warming** (D > 24°), **close** (12° ≤ D ≤ 24°), **locked** (D < 12°).
2. Map each band to a distinct visual (colour + motion, never text) and a distinct sound (see `SOUND-MAP.md`).
3. Tune the thresholds against your own hand across all four fixtures; record the tuning table.
4. Add hysteresis: a band only changes after 150 ms in the new state, so the display never strobes.
5. Delete every string in the UI that could read as an error.

## Done when
- [x] Three bands with tuned, recorded thresholds — 12° / 24° + a 2° release, each with the
      measurement that chose it (`band-tuning.md` §2–§5)
- [x] No hysteresis flicker over a 30 s test — **offline**: 0 changes in 300 × 30 s runs with the
      shipped damping, vs 1083/30 s undamped (`band_sim.py` §2). The device run of the same test is
      still open; the overlay now carries a live `changes/30s` counter so it is a read, not a judgement
- [x] Zero error strings in the build — `scripts/lint_copy.py`, 0 violations, and the two dev views
      that contain verdict-shaped words are gated out of release builds
