# P2.5 — The lock payoff: the shape becomes an object

**Phase:** P2 · **Est:** 1.5 h · **Depends on:** P2.4 · **Workstream:** W1
**Gate fed:** G2

## Why this exists
The first lock is the product's first reward, and it happens inside 75 seconds. If it doesn't feel like an event, the whole loop is flat.

## Do this
1. On lock: the reference hand dissolves (scale + fade over ~400 ms) and re-forms as a small object.
2. The object travels along a gentle arc to a temporary anchor point (the shelf arrives in P4).
3. Play the signature lock chime; add a brief controller-free haptic substitute (a subtle pulse in the hand visual).
4. Test the timing: the whole payoff must complete in under 1.2 s so it never feels like a cutscene.
5. Record it — this is the 0:45 shot in the submission video.

## Done when
- [x] Lock payoff completes in <1.2 s — **0.99 s** of a 1.20 s budget, asserted by `LockPayoff.TotalSeconds`
      and by `scripts/payoff_previs.py` (which also asserts the no-empty-frame overlap)
- [x] The dissolution reads as *transformation*, not deletion — brighten-while-shrinking, a 0.10 s overlap,
      a crossfade through the hand, and a settle at the anchor (`lock-payoff.md` §2)
- [ ] Footage captured for the video — **blocked** (no Unity, no headset). Shot list is written; a previs
      exists and is explicitly not a substitute
