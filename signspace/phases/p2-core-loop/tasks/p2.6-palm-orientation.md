# P2.6 — Weight palm orientation separately from finger angles

**Phase:** P2 · **Est:** 1 h · **Depends on:** P2.2 · **Workstream:** W2
**Gate fed:** G2

## Why this exists
Several sign pairs differ mostly in which way the palm faces. If palm orientation is folded into the finger average, the app will accept a correct-shape/wrong-facing attempt — which for a sign learner is a different word.

## Do this
1. Compute a palm basis: wrist forward vector plus index-knuckle plane normal. Compare against the target's basis.
2. Produce a separate orientation error `O` in degrees.
3. Combine: `D_total = D_fingers + k · max(0, O − O_slack)` with `O_slack` ≈ 15° and `k` tuned.
4. Test with the two most orientation-sensitive shapes in the set (C/O pair and A/B).
5. Record the sensitivity curve in the tuning notes.

## Done when
- [ ] Palm orientation contributes independently
- [ ] A deliberately mis-facing hand fails to lock
- [ ] `k` and `O_slack` recorded

## Traps
- Using Euler angles — gimbal ambiguity will produce phantom errors at certain wrist rotations
