# P6.7 — Write the accessibility doc to the build, not to the aspiration

**Phase:** P6 · **Est:** 1 h · **Depends on:** P6.5 · **Workstream:** W3
**Gate fed:** G6

## Why this exists
The submission will be read against what shipped. A doc that overstates is a liability in front of a panel that might actually test it.

## Do this
1. List each accessibility path and its actual playthrough evidence (recording filename).
2. State the claims we are **not** making: no clinical validation, no diagnosis, no medical use.
3. Note known gaps honestly (e.g. two-handed shapes out of scope).
4. Cross-check every sentence against the build.

## Done when
- [ ] Every claim traceable to a recording
- [ ] Explicit non-claims section
- [ ] No aspirational language

## Artefacts produced
- `docs/03-content/ACCESSIBILITY.md` (complete)

## Traps
- Letting the doc describe the design intention instead of the shipped behaviour
