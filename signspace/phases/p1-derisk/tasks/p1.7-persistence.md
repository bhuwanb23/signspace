# P1.7 — Survive a relaunch: the cube is still there

**Phase:** P1 · **Est:** 45 min · **Depends on:** P1.6 · **Workstream:** W2
**Gate fed:** G1

## Why this exists
The shelf's entire value is temporal — it only means something if it's still there tomorrow. Persistence is cheap now and expensive on Day 9.

## Do this
1. Save the anchor reference (room UUID + anchor GUID) plus a local position offset to disk on placement.
2. On launch, re-resolve the anchor and restore the cube's transform.
3. Kill the app from the recent-apps menu, relaunch, confirm the cube returns to the same physical spot.
4. Repeat after a headset reboot.
5. Record how long re-resolution takes and what happens when the room can't be re-found.

### Three decisions the log defends

1. **Identity is `OVRAnchor.Uuid`, not `anchor.name`.** Meta: *"UUIDs persist across sessions."* An
   object name like `TABLE_1` is generated at load time; a name match is scored 10 against a UUID
   match's 100, so it is visible in the log as second-best.
2. **The offset is anchor-local, and the shelf is parented to the anchor.** The tracking origin is not
   preserved across sessions, so a world position returns offset by however far it moved. The shelf
   inherits the runtime's own correction instead.
3. **The trap is measured, not asserted.** `lastWorldPos` is stored for one purpose only: on restore,
   `worldDriftM` reports how far the origin moved — i.e. exactly the error a world-position save would
   have produced. If that number comes back 0.000, the test cannot distinguish the two designs and the
   log says so rather than claiming a win.

**Not-found is normal, not an error path:** the save is always kept, the plinth appears with no
message, and the anchor is retried next launch. Walking into another room must never delete progress
("the shelf belongs to a surface, not to a person" — `SaveSystem`).
