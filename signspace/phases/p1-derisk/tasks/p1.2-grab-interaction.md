**Deviation, with the reason recorded in `grab-log.md` §3:** steps 1–2 name the ISDK
`HandGrabInteractable` / `HandGrabInteractor`. This build uses a purpose-built `Grabbable` +
`PinchGrabber` instead, because ISDK grab requires its own ISDK `Hand`/`HandGrabApi` rig, which would
mean a second hand pipeline running beside `MetaHandSource` — and P1.2's job is to prove **our**
pipeline drives grab. Meta's recommendation to use the SDK is quoted in the log rather than ignored,
along with the condition that would reopen the decision.

## Why this exists
Grab is the input for the entire core mechanic. It must work on a hand-held object in mid-air, with no ray and no controller.

## Do this
1. Add an ISDK `HandGrabInteractable` to a test cube plus a `HandGrabInteractor` on each hand.
2. Configure grab type to pinch, with a generous pinch threshold for reliability.
3. Disable ray interaction in the scene so nothing can silently fall back.
4. Test: can you grab, move, and release a floating cube with either hand, 20 times, without a miss?
5. Log miss rate. If >2 misses in 20, widen the grab threshold before proceeding.

## Done when
- [ ] 20/20 successful grabs with each hand — ⬜ **device**, table in `grab-log.md` §1
- [ ] No ray or controller fallback active — 🟡 **enforced by `NoFallbackGuard`** at runtime; verified by scan, not by assertion
- [ ] Miss rate recorded — 🟡 **instrumented**: every attempt logged with its distance, so a miss is explainable rather than averaged
