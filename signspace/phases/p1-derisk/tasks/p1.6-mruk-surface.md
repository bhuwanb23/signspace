# P1.6 — Find a horizontal surface and anchor a cube to it

**Phase:** P1 · **Est:** 1 h · **Depends on:** P0.4 · **Workstream:** W2
**Gate fed:** G1

## Why this exists
MRUK is a named rubric technology and the shelf depends on it. Detection must be proven before the shelf is designed around it.

## Do this
1. Enable MRUK in the project and initialise it on scene start.
2. Query the current room for horizontal surfaces at a comfortable height.
3. Spawn a test cube at the nearest suitable surface, offset slightly above it.
4. Test in four conditions: a clean desk, a lap, a bed, and a cluttered table.
5. Record which conditions work and how long detection takes from launch.

## Done when
- [ ] Cube sits on real furniture in at least 2 of 4 conditions
- [ ] Time-to-detection measured
- [ ] Failure conditions documented

### Three defects found and fixed before the first reading

Verifying the four `[VERIFY]` names against the v207 reference turned up three real problems, not just
typos. Two of them would each have produced a false "MRUK does not work" verdict:

1. **Volumes were skipped.** Only `PlaneRect` was accepted, but Meta documents tables and couches as
   **volume** anchors (`VolumeBounds`) — the finder was skipping its main target.
2. **Prefab rooms were rejected.** The draft required `HasValidHandle`, and Meta states that anchors
   loaded from JSON or Prefabs *do not have a valid handle* — so every Meta XR Simulator run (every
   run before the headset arrives) would have reported zero surfaces.
3. **Geometry assumed world-aligned local axes.** The tabletop point now comes from
   `GetClosestSurfacePosition`, which returns a point and normal regardless of anchor rotation.

Both traps are handled in code, not in prose: detection latency is measured twice from `Awake()`
(trap a), and a missing surface returns `false` with a sentence naming the filter that rejected it
while `ShelfAnchor` keeps running on its plinth (trap b).
