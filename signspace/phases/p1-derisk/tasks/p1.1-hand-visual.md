**Re-scoped before writing, with the reason recorded:** this task assumes a tracking pipeline exists
and needs a better mesh. It did not exist — `AutoBind` had zero callers and nothing implemented
`IHandStateProvider`, so the matcher was fed an empty joint array and grab could never fire. The mesh
step ("import a low-poly hand mesh") is **not** followed: `HandVisual` already generates one from the
canonical joints, and importing a second hand would force the 26→20 remap this task's own trap list
warns about.

## Why this exists
The stock ISDK hand reads as a demo. Ours is the product's main character — and a custom visual is also the cheapest way to prove we control the tracking pipeline rather than inheriting whatever the sample did.

## Do this
1. Import a low-poly hand mesh with at least 5 fingers and a palm, skinned to 26 joints.
2. Wire `OVRSkeleton` (or the OpenXR hand equivalent under the v207 rig) to drive joint transforms each frame.
3. Assign the mesh to both hands; verify wrist, finger spread and thumb opposition read correctly.
4. Add a confidence readout from the tracker's hand confidence value, visible only in a debug build.
5. Measure: triangle count, draw calls, and frame time with both hands tracked.

## Done when
- [ ] Both hands render and track with no visible lag — ⬜ **device**
- [ ] Joint count and names documented — 🟡 **instrumented**: `hand-joint-report.txt` is written on first bind; the numbers land in `POSE-FORMAT.md` §1.1 the moment it is pulled off the headset
- [ ] Frame time impact measured, not estimated — ⬜ **device** (OVR Metrics Tool, P1.8's rig)
