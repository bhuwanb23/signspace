# P8.3 — Write the friction log

**Phase:** P8 · **Est:** 1 h · **Depends on:** P8.2 · **Workstream:** W1
**Gate fed:** G8

## Why this exists
A friction log is only useful if it is uncomfortable. Ten rows minimum, and the worst ones first.

## Do this
1. List every moment a tester stopped moving or made a wrong assumption.
2. For each: what they did, what they expected, what the app showed.
3. Rank by how much damage it does to a judge in the first 90 seconds.
4. Cross-check against `FIRST-FIVE-MINUTES.md` — if the design doc predicted the friction, that's a design-doc failure worth noting.

## Done when
- [ ] ≥10 rows, ranked
- [ ] Each row has behaviour + expectation + app response
- [ ] Fixes scoped to the top three

## Artefacts produced
- `docs/05-build/PLAYTEST-LOG.md` (complete)

## Traps
- Softening the log — it is the only honest measure in the project
