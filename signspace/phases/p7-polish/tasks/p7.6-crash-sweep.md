# P7.6 — Crash sweep

**Phase:** P7 · **Est:** 1 h · **Depends on:** P7.5 · **Workstream:** W2
**Gate fed:** G7

## Why this exists
A single crash in front of a judge outweighs every good decision in the build. This is the cheapest insurance available.

## Do this
1. 20 cold launches, back to back, with a script of actions each time.
2. 5 mid-session backgroundings, 2 device sleeps, 1 reboot.
3. Try the four hostile conditions: no surface, no eye tracking, tracking lost entirely, room changed.
4. Fix everything that crashes; document anything that merely misbehaves.
5. Record the results as a table.

## Done when
- [ ] 0 crashes over 20 launches — **NOT RUN**
- [ ] 0 crashes across the hostile conditions — **NOT RUN** on device (all five have a code path and a desk check)
- [x] Misbehaviours documented — `crash-sweep.md`

## Build status (17 Nov 2026)

**Shipped.** `HostileGuard`: a five-row table (no camera, no surface, no eye tracking, tracking lost,
room changed) where each row names the answer and what it disables; the runtime logs each condition
once and disables the subsystems that would dereference a null. `P7.6 Check crash posture` asserts the
table is complete and unique, and drives the no-camera path by actually disabling the camera.

**Two hardening fixes in this phase.** The tray's shader lookup could throw at `Start` on a stripped
shader (`new Material(null)`); it now falls back and warns. The boot probe's CSV write is wrapped: a
probe must never be the crash it was measuring.

**NOT RUN:** all twenty launches, the sleep/reboot rows, and the four hostile conditions on hardware.
