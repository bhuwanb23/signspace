# P7.5 — Cold boot and stability sweep

**Phase:** P7 · **Est:** 45 min · **Depends on:** P7.4 · **Workstream:** W2
**Gate fed:** G7

## Why this exists
A judge launches the app once, cold, possibly impatient. The first ten seconds decide whether they see the product or a loading screen.

## Do this
1. Measure cold boot to first interactive frame, five times. Median <15 s.
2. Remove or shorten any splash; no logo animation longer than 1 s.
3. Background and foreground the app mid-session ×5; confirm the loop resumes.
4. Confirm the shelf and calibration restore correctly after each backgrounding.

## Done when
- [ ] Median cold boot <15 s — **NOT RUN** (`boot-times.csv` has no device rows)
- [ ] 5/5 background/foreground cycles resume cleanly — **NOT RUN**
- [x] No splash over 1 s — the splash is **static** (one frame, no dolly, no zoom), set by `SplashSettings`

## Artefacts produced
- `phases/p7-polish/boot-times.csv`

## Traps
- First-launch MRUK detection blocking the whole app — the loop must be playable before the shelf resolves

## Build status (17 Nov 2026)

**Shipped.** `BootProbe` writes `utc,startup_ms,hands_ms,interactive_ms,resumes,resume_ms` per launch to
`Application.persistentDataPath/boot-times.csv`. Crucially, `interactive_ms` waits for **hand + shelf**,
and the plinth counts, so "playable before MRUK resolves" is measured rather than asserted. It refuses
to write a row in the editor, because an editor launch is not a cold boot, and a failed write is a
warning rather than an exception.

**Splash.** Unity's logo cannot be removed on this licence. It can be stopped from animating: the
splash is now static, which is the honest maximum. `P7.5 Check boot readiness` asserts it.

**NOT RUN:** the five launches, the median, and the background/foreground cycles. `boot-times.csv`
carries the header and the NOT RUN rows, so there is nothing to misread as a measurement.
