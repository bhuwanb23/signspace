# P3.1 — Build the near-miss: name the sign they actually made

**Phase:** P3 · **Est:** 2.5 h · **Depends on:** P2.2 · **Workstream:** W2
**Gate fed:** G3

## Why this exists
Every competitor returns correct/incorrect. Naming the *confusable* sign is the single thing no prior project does (see `NOVELTY-AND-PRIOR-ART.md` N1), and it is the product's best three seconds of video.

## Do this
1. For every target shape, precompute the pairwise distance from that target to each of the other **5** shapes in the shipped set.
2. At runtime, compute the user's distance to *all six* at once (cost is trivial: 6 × 26 joint angles).
3. Rule: if `D(target) > locked_band` **and** `D(other) < locked_band` for exactly one other shape, fire the near-miss naming `other`.
4. If two or more others qualify, stay silent — ambiguity is not a diagnosis.
5. Do **not** put the degree number in the message: the shipped copy is the five-word line in
   [`../copy-variants.md`](../copy-variants.md). The magnitude stays in the log, for tuning.
6. Test by deliberately making each of the **4** pairs the shipped set contains — B↔U, U↔V, V↔W, C↔O.
   `SIGNSET.md` §5 lists 8; the other four need shapes deferred to P5's 12-shape build.

## Done when
- [ ] All 4 shipped-set pairs fire correctly (36-pair rule test: [`../near-miss-test.csv`](../near-miss-test.csv))
- [ ] Two-other ambiguity produces silence
- [ ] Magnitude logged and plausible in the 5–20° range, never shown on screen

## Artefacts produced
- `unity/Assets/_Project/Scripts/Matching/Matcher.cs` — the near-miss rule lives in the matcher, not a separate `NearMiss.cs`
- `phases/p3-feedback/near-miss-test.csv`

## Traps
- Computing distance only to the target and then guessing the nearest — compute all 12, it is free
- Firing on the second-nearest when the first is nearly as close
