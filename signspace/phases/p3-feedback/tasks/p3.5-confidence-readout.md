# P3.5 — Live confidence readout that pauses instead of failing

**Phase:** P3 · **Est:** 1 h · **Depends on:** P3.2 · **Workstream:** W2
**Gate fed:** G3

## Why this exists
When tracking degrades the app must visibly stop measuring, not quietly mis-measure. This is the behaviour that makes the fragility honest instead of confusing.

## Do this
1. Add a subtle indicator that dims when confidence is below the floor.
2. Freeze the hold timer, dim the match display, and show *'watching'* state (no words if possible — a visual pulse).
3. Resume automatically when confidence returns.
4. Test by occluding a hand behind the other, moving fast, and leaving the room's lights low.
5. Confirm no lock can ever be awarded while confidence is below the floor.

## Done when
- [~] Pause behaviour proven in three degradation scenarios — proven against the state machine
      (`scripts/pause_sim.py`: 0 locks below the floor in all three, 1 each with the floor removed as the
      control), **not yet on a headset**. P3.6 carries the hardware run
- [x] No lock awarded below the floor — the control is the proof: with the floor removed the same three

## What was built, and what was refused

| Decision | Why |
|---|---|
| A lamp that **dims and breathes**, no words | a frozen number reads as a stalled app; an error message reads as blame; a slow pulse reads as waiting |
| **Enters on the first untrustworthy frame, leaves after 0.25 s above floor + 0.05** | honest immediately, and not strobing: 20 visible state changes over 4 s at the floor without the window, 1 with it |
| Never dims to black, never changes hue | black is indistinguishable from a crash, and colour belongs to the band |
| `TrackingConfidence` owns **no timing that matters** | the freeze is `Matcher`/`HoldTimer`; delete this class and the pause still happens, which is why it is safe to ship |
| Pause, never penalise | the hold freezes where it stood and resumes; `pause_sim.py` asserts the resume, because a "pause" that loses progress is a penalty with a nicer name |

## Review, after the first pass

Two defects were found by reading the code back rather than by running it, and both are the kind that
survive a demo:

1. **The meter could not be dimmed from outside.** `BandFeedback` repaints the halo's colour through a
   `MaterialPropertyBlock` every frame, so `TrackingConfidence` setting `_BaseColor` on the material was
   overwritten immediately — implemented, compiled, invisible. The dim moved into `BandFeedback`
   (`pauseDim`), where the block lives.
2. **The dim scaled alpha.** Unlit materials are opaque; alpha changes nothing. Both the lamp and the
   halo now scale RGB.

Both are recorded in `phases/p3-feedback/pause-behaviour.md`, because the pattern — *a change that
looks implemented* — is the one that costs a demo.
